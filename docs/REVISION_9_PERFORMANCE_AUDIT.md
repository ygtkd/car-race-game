# 改修9 描画負荷の再確認
測定日: 2026-09-26。対象: 改修8 `b89280ee95e6`、改修9 `44db0ee151c0`。今回、ゲーム本体のコード・モデル・公開ビルドは変更していない。

## 結論
このPCのAMD Radeon GPUを使った測定では、下表の軽量設定・静止場面で30回/秒前後の描画更新を確認した。スマホでの30 fps維持や、走行中・エフェクト集中時の性能を保証する測定ではない。

改修9で描画負荷は増えている。湘南のコースモデルは三角形が67,432から79,426へ約17.8%、頂点が106,120から127,030へ約19.7%増加。Apex車体も7,816から9,148三角形へ約17.0%増加した。描画処理の余裕が少ない環境向けには軽量化の余地がある。

夜の8台分のヘッドライト計算、広い範囲を一体化した景観メッシュ、内部描画解像度が主な確認対象。星や月だけが原因だと断定する証拠はない。

## 測定方法と前回値の訂正
- Headless Edge 154、CSS表示領域1100×650、タッチ5点、軽量設定0（描画距離500m、目標30 fps）。通常の内部解像度1100×650。半解像度比較のみ550×325で、CSS領域と視野は維持。
- Unityへ同じ条件の検証用スナップショットを送り、受信したraceId・台数・昼夜を確認後、3.5秒待機。各条件を4.5秒×2回測定。HTMLメニュー/HUDを非表示にし、3D処理を切り分けた。
- 8台の車体をロードし、自車以外は後方に配置。すべての車が同時に画面に映る最悪条件ではない。phase=menuの静止場面なので走行シミュレーション、通信遅延、妨害エフェクト、音響負荷は対象外。
- WebGLの描画命令を数え、描画命令が出たブラウザーフレームの頻度・命令数・投入三角形数を測定。GPU処理完了時間・ディスプレイの実表示FPS・実際に見えたポリゴン数ではない。計測用ラッパーの負荷も含む。
- 前回のrequestAnimationFrame間隔はUnityの描画フレーム間隔ではなかった。タッチ端末の初期設定は30 fpsで、ブラウザーだけが約60回/秒更新する場合もある。前回表の16.8msをゲームの約60 fpsと読んではいけない。
- コースの起伏や配置も変化しているため、新旧比較は近い地点の代表場面比較。カメラ画像が完全に同一の比較ではない。開始位置の変更を避け、橋入口・島内・市街地を共通の平面座標付近で選定した。
- nativeでは実際のGL rendererがAMD Radeon / Direct3D11であることを確認。SwiftShaderはGPUの代わりにCPUで描画する比較用条件で、スマホ性能を表さない。2種類を同時実行していない。
- 合計56サンプル、実行時エラー0。実機iPhone/Galaxy/Pixel、長時間発熱、全コース全区間、標準品質60 fpsは未検証。

## コード・モデルから確認した要因
1. **夜間照明** — `Assets/Resources/CoastSurface.shader` は各画素に最大8台分の距離・方向計算を行う。軽量設定でも照明台数は減らない。昼の分岐はこのループを通らない。
2. **広域メッシュ** — `Art/Blender/build_assets.py:109` の結合キーはグループと材質で、空間区画ではない。湘南31パーツ中16、鈴鹿15パーツ中14、山岳15パーツ中7の外接範囲が500mを超える。画面外の木・建物も同じメッシュに含まれると、頂点処理の省略が効きにくい。モデルの外接範囲と三角形数はJSONにも記録。
3. **解像度** — HTMLのDPR上限は1.5。DPR=1に比べると同じCSS寸法で画素数は2.25倍。軽量設定は現在、DPR自体を下げない。
4. **裏面処理** — Surface全体が`Cull Off`。閉じた車体・建物にも適用される。道路や葉など両面が必要な形状と分ける余地がある。削減効果は未測定。
5. **CPU側の二次要因** — 各車の更新でヘッドライト配列を再送している。車輪接地の`RoadDistance`は呼出しごとに小さな配列を生成する。今回の静止場面でこれらが主なボトルネックだったとは確認していない。

## 次に軽量化する場合の優先順位
1. 軽量設定では近い・見えるヘッドライトを優先し、照明数や遠方での計算を制限する。自車の視認性を維持し、夜8台で比較する。
2. 内部描画解像度を端末性能に合わせる。UIの大きさを変えず、見た目と負荷を比較する。
3. 景観を適度な区間に分割し、遠方モデルに簡略版を使う。区画を細かくしすぎた描画命令増加と、頂点削減の釣り合いを測る。道路や橋を消して軽量化しない。
4. 必要に応じて空のノイズ計算、閉じた物体の裏面処理、ライト情報送信回数、車輪計算の一時配列を見直す。
5. 変更後に実機3系統で8台レース・夜・スペシャル同時発動・連続走行を確認する。

今回の依頼は負荷の確認のため、上記最適化は未実装。新規インストール、push、Azure公開なし。
