## 目的と指示の優先順位
現在公開中のCOAST RACERについて、これまでの要望と実機での不一致を解消してください。プロンプトの文言変更だけで完了せず、実装・ビルド・配信・実際の表示を個別に確認してください。
本書は新規の追加改修指示です。既存のプロンプトは履歴として残し、上書きしないでください。
優先順位は「最新のユーザー指示 ＞ 本書 ＞ COAST_RACER_RACE_FLOW_REVISION_PROMPT.md ＞ COAST_RACER_MOBILE_REVISION_PROMPT.md ＞ それ以前の要望」です。既存コードにある挙動を正しい仕様と決めつけないでください。

特に以下の旧仕様は廃止されています。
| 旧仕様 | 今回の正しい仕様 |
| --- | --- |
| 設定ボタンが左上 | 全画面で右上。枠なし |
| 開始時に3、2、1やスタート・GOの文字を表示 | 信号とブザーのみ。開始の数字・文言は表示しない |
| 通常のコース外警告と別の大幅逸脱カウント | 緑の芝生上だけで5秒の復帰警告。緑以外では非表示・解除 |

| 先頭のゴールから90秒で全員終了 | 指定された完走人数・CPUのみの条件で終了 |
| コース・車体を選んでから部屋作成 | マルチ選択直後に部屋作成・参加 |
| 3周、4台固定、同時接続2人 | 全コース2周、オンラインは人間＋CPUで最大8台 |

## P0-1. ホーム画面起動での旧表示・反映不一致
- 通常ブラウザーで最新版が表示されるだけでは合格にしない。ホーム画面からの起動、起動済み画面への復帰、完全終了後の起動を区別する。
- 実行中の画面が使うHTML・JS・CSS・Unity data/wasm/frameworkの版が一致していることを確認できる仕組みを用意する。ゲーム設定内に控えめなビルド識別情報を表示し、報告時に照合できるようにする。
- 同じファイル名の古いキャッシュ、読み込み済み画面、古い起動URL、ビルドへのコピー漏れを切り分ける。原因をキャッシュと決めつけない。
- HTMLだけ、CSSだけ更新されて旧Unityや旧JSが混在しないよう、配信ファイル全体を一つのリリースとして管理する。
- 更新検知時はレースを強制終了せず、メニューで安全に更新できるようにする。名前・音量・バッジを削除しない。ホーム画面アイコン削除や保存データ消去を通常の解決方法にしない。
- 実機にアクセスできない場合、実機で直ったとは報告せず、実行版と再現状況をユーザーと照合する手順を残す。

## P0-2. レース開始時の数字・文言を完全に非表示
- スタート演出中の「3」「2」「1」「スタート」「START」「GO」などを表示しない。信号とブザーだけで開始を知らせる。
- 内部の開始待機時間は残す。待機中は走行不可。オンラインは全員のロード後、サーバー主導で同時開始する。
- DOMだけでなくUnity側の描画、翻訳の適用、状態更新、再戦、再接続から文字が再表示されないか確認する。
- 未使用の翻訳キーがあるだけで不具合と断定しない。実際に表示される要素とその生成経路を特定する。
- この削除対象はレース開始演出。コース選択画面の開始ボタン、周回数、ラップタイム、芝生の復帰までの秒数は削除しない。
- 合格条件: ソロ・マルチの初回と再戦で、開始待機から走り出しまで画面を連続観測し、信号以外の開始数字・文字が一度も表示されない。

## P0-3. 緑の芝生以外では復帰警告を出さない
- 道路、縁石、舗装部分、ゴールライン上では「コースに戻ってください」も復帰秒数も表示しない。
- 緑の走行不可領域に入ったときだけ「コースに戻ってください 5秒」から表示する。秒数を伴わない通常警告は廃止する。
- 判定は見た目の緑の領域と一致させる。幅の数値を別々にハードコードするのではなく、描画と走行判定が同じ領域定義を使う。
- 車体基準点が緑に入った時点で連続5秒を計測する。緑から出たら表示と時間を解除し、再び入ったら5秒から開始する。
- 現実装の「8.1mで開始、6.8mまで戻らないと解除」という中間領域で、文字や残秒が止まって残る問題を解消する。境界の安定化処理で非芝生上に警告を残さない。
- ポーズ、結果、メニュー、別レースへ古い警告を持ち越さない。オンラインはサーバーの正しい状態に追従する。
- 合格条件: 両コースで道路→縁石→芝生→縁石→道路を移動し、緑上だけで表示すること、4秒で道路に戻れば復帰しないこと、連続5秒の逸脱で復帰することを確認する。

## P0-4. 逸脱直前の道路中央への復帰
- 正常走行中に道路区間ID、区間内位置、中心線座標、高さ、道路の向きを保存する。芝生では上書きしない。
- 復帰時はその保存値を使い、逸脱後の位置から道路区間を再検索しない。最後のチェックポイントへ戻さない。
- 鈴鹿の立体交差で上下の道路を取り違えない。遠くへ逸脱しても最後の道路区間に戻す。
- 速度を安全にリセットし、既存の復帰ペナルティ・接触保護を維持する。瞬間移動でチェックポイント、周回、走行距離、ゲージを加算しない。
- 合格条件: 同じチェックポイント区間内の異なる2箇所から逸脱し、それぞれの直前位置に対応した中心へ戻る。立体交差でも確認する。

## P1-1. 設定と一時停止
- 歯車はメニュー、選択、ロビー、レース、結果など表示対象の全画面で右上。枠なし。左上は戻る「＜」専用とする。
- 一時停止はレースヘッダー内の右端。歯車とは重ねない。
- ホーム画面起動時のセーフエリアと画面回転でも実座標・タッチ可能範囲を確認する。CSSの文字列確認だけで完了しない。

## P1-2. ゴールラインと表示車体の一致
- 必須チェックポイントを通過した2周目に、車体前端が目に見えるゴールラインの判定面を正方向に越えた瞬間に完走する。
- 物理位置だけでなく表示補間とのずれを確認し、表示車両が手前にいるのに結果画面へ切り替わる現象を解消する。
- 高速通過、接触による押し出し、逆走、ライン往復、復帰、複数台の同時通過を検証する。サーバー確定時刻と表示タイミングを混同しない。

## P1-3. 結果・ランキング・終了・再戦
- 結果の「記録は保存しています」等の説明文を表示しない。必要な保存処理は維持する。
- ソロ: 人間プレイヤーが完走した時点で、未完走CPUだけの順位・タイムを推定して表示する。既に完走した車の実測は維持する。
- CPUの残距離は正規に通過したチェックポイントと残り周回から求め、コースを外れた位置や近道で不当に短くしない。車種性能とコースに応じて推定する。
- 人間のタイムは自動計算しない。人間の実測完走だけをベスト・ランキングに反映する。CPUは実測・推定とも対象外。
- マルチ: 自分の完走後に結果を表示し、他車完走ごとに全員の画面で順位・タイムを更新する。
- 通常はN−1台の完走で残り1台を最下位・記録なしとして終了する。未完走がCPUのみなら推定して終了。ただし残り1台の記録なしを優先する。
- 同一更新内の全車ゴールは全車の実測を優先する。先頭完走から90秒で終了する旧処理を削除する。他の時間制限を勝手にレースの完走条件へ混ぜない。
- 切断者は再接続猶予中に自動でCPUと見なさない。猶予終了後の離脱順位と、継続車の順位を区別する。通常終了条件と切断終了条件を文書化し、曖昧な場合はユーザーに確認する。
- 結果表示を維持したままの再戦準備を全参加者で検証する。古いレースのfinished状態により、ロビーへ戻った直後に結果画面へ押し戻されないようにする。
- 結果保存、バッジ獲得、終了通知を再送・再接続・再戦で二重実行しない。

## P1-4. マルチプレイのルーム
- マルチ選択の最初に作成・参加・参加可能ルーム一覧を表示する。
- ホストはコース、CPU数0〜7、自分の車体を選ぶ。ゲストは自分の車体だけを選ぶ。人間＋CPUは最大8台。
- CPUが占有する枠を含めて定員を計算する。満員・開始済み・終了済み・期限切れへの新規入室は禁止。
- 全員の決定後に自動ロード、全員ロード後に信号開始。構成変更や参加・退出で必要な準備状態を解除する。
- ホスト退出時は残る人間へ移譲。人間がいないルームを不要に残さない。
- 画面上でCPU数を入力しやすくし、サーバーの定期更新で入力中の値を勝手に戻さない。ゲストにも確定CPU数・コース・参加人数が分かるようにする。

## P1-5. 通信異常時の終了
- 明示退室、不正データ、送受信例外、無応答、接続中断を区別し、ソケット・タイマー・イベントハンドラー・入力・参加情報を必ず解放する。
- 一時的な通信断では最大20秒の復旧猶予。猶予終了後に確実に終了する。不正プロトコルや明示退室は再接続を繰り返さない。
- 15秒無応答で直接終了する経路と20秒再接続経路の不整合を整理し、無応答を検知してからの復旧方針を一貫させる。
- 古いソケットの通知が新しいルームを変更しない。異常後の再入室で接続枠が漏れない。
- ホーム画面アプリのバックグラウンド・復帰、Wi-Fi切替、機内モード、サーバー切断も検証対象にする。

## P1-6. バッジと車体
- バナナボートは1本の船体。車体選択、図鑑、レース、マルチで同じモデルを使う。
- バッジは種類を識別できる画像と名前を表示し、共通の◆文字だけで代用しない。
- 結果からメニューへ戻る際、そのレースで新規獲得したものだけを表示する。新規獲得がなければ表示しない。
- 保留表示をレースIDごとに管理し、連続再戦、結果の更新、再接続、再読み込みで別レース分を混ぜたり重複獲得したりしない。
- 実際の完走による獲得経路を確認する。人工的な結果データを注入したテストだけで合格にしない。

## P2. 背景・雲と既存要望の再確認
- 山岳は山並み・森林・岩、鈴鹿は観客席・ピット・フェンス・周辺施設などが分かる背景にする。鈴鹿の遠景をほぼ平坦な色面だけで済ませない。
- 空に雲を表示する。高低差、立体交差、進行方向が変わっても不自然な切れ目や大きな破綻がないことを確認する。
- 下記の過去要望は実装済みと推測して省略せず、対応表に証拠を残す。既に正しく動く機能は不用意に作り直さない。
  - 日本語デフォルト、設定内の言語・名前・BGM音量・SE音量、ログイン不要の端末プロフィール。
  - メニューと図鑑、360度表示、ステータスバー、装飾、記録、8車種固有スペシャル。
  - シンプルなUI、開始前のコース非表示、遷移とロード画面。
  - ユーロビート調レースBGM、メニュー・結果BGM、クリック音、速度連動エンジン音、ミュート・復帰。
  - 半径ではなく直径を半分にした円形メーター、長方形で幅2倍の左右タッチ操舵、ペダルとの同時操作。
  - 長押し選択とダブルタップ拡大の抑止、入力欄の編集、必要なスクロール、指が離れた後の入力解除。
  - 全コース2周、共有コイン3枚、取得後2秒で再出現、他者が取得中は取得不可、車体衝突。
  - COAST RACERの名称・ホーム画面アイコン、戻る「＜」、設定の×と背景タップ、一時停止の中央配置と退出確認。
  - アシスト付き運転、コース形状と勾配、追加車種を含むバランス、名前の車上表示。
- 実機の質感や音楽の印象は静的テストでは証明できない。確認方法と未確認事項を区別する。
