# COAST RACER 改修プロンプト9

作成日: 2026-09-26。基準: 改修8、公開Build `b89280ee95e6`、実装コミット `a66792fd68481999db3419c90a4f8ec70bca8baa`。

この文書を新しい改修指示として使用してください。過去のプロンプトは上書きしないでください。今回の依頼はプロンプト作成までです。実装・push・Azure公開は、別途実行指示を受けてから行ってください。

## 1. 目的と維持する仕様

メニューの重複する設定入口を整理し、夜空と湘南の昼の太陽を美しくしてください。湘南海岸を、中央の高い丘と起伏、変化のあるコーナー、豊かな沿道景観があるコースへ改修してください。報酬通知は「達成した内容」と「入手したアイテム」の2段表示にしてください。さらに、四輪車のタイヤ位置・向き・接地を修正し、実際に使用した配置コードを提示してください。

- COAST RACER、日本語初期設定、スマホWeb、2周、最大8台、全10車種、30ミッション、CPU5段階、昼夜、オンライン、ログイン不要を維持する。
- 改修8のファンファーレ・ゴールカメラ・CPU強化・妨害30m・耐性・スリップストリーム・コーナーボーナスを維持する。
- 設定の名前・言語・音量・効果音・ミュート、右上のSVG歯車、暗い背景の設定ダイアログと閉じ方を維持する。
- 灰色路肩は減速のみで警告なし。芝生逸脱時だけ5秒警告し、直前に走っていた道路の中心へ戻す。
- ゲーム開始前に選択コースが背景へ出る問題、周回不成立、入力の押しっぱなし、地形の浮き・透過・路面被覆を再発させない。
- Blenderの編集用モデル・生成スクリプト・Unity用メッシュ、共有走行ロジック、オンラインサーバー、Web UI、WebGLビルドを整合させる。
- Azure App Service Free／SQL Database Freeの構成を維持する。
- `Assets/Scripts/CarController.cs` の既存ユーザー変更は上書き・無断で取り込まない。
- 新規インストールは名称・バージョン・用途を記録する。空き容量1GiB未満または中断指示があった場合は進捗を保存して中断する。

## 2. メニューの「ゲーム設定」ボタンを削除

- メニュー内の文字付き「ゲーム設定」ボタンだけを削除する。
- 右上の歯車は残す。メニューでも歯車から設定を開けること。レース中など他画面の歯車も維持する。
- 設定画面のタイトルやアクセシビリティ用の「ゲーム設定」は削除しない。
- ボタンを消した分の空行・余白・フォーカス対象を残さず、既存のシンプルなメニューを自然に詰める。
- 現在の `racer.js` は `settingsButton`、`menuSettings`、`raceSettings` に連結してイベントを設定している。DOMだけを削除してnull参照を起こさないよう、イベント設定・CSS・テストの参照も修正する。
- 歯車の右上位置、枠なしSVGデザイン、タッチ領域、名前や音量等の保存は変えない。

## 3. 全コースの夜空に星と月

- 山岳・鈴鹿・湘南すべての夜モードに、美しい星空と月を追加する。
- 星は大きさ・明るさ・密度に自然なばらつきを持たせる。規則的な水玉模様や大粒の球体の並びにしない。瞬きは入れる場合も控えめにし、点滅の強い演出は避ける。
- 月は輪郭が滑らかで、陰影や淡い光のにじみを持つ見た目にする。月相は固定でよい。昼用の太陽と同時表示しない。
- 星と月は空の遠景として描画し、カメラ移動で近距離の物体のように動かない。山・建物・橋・トンネルより手前に描かない。雲の遮蔽や明るさも不自然にならないよう調整する。
- 夜の暗さと車のヘッドライトを維持する。空だけを明るくしすぎて昼のようにしたり、UIや道路の視認性を落としたりしない。
- 空用シェーダー、スカイドーム、共有メッシュ等の軽量な方法を優先する。星ごとのGameObject・リアルタイムライト・物理判定は作らない。
- 昼夜切り替え・コース変更・再戦で表示が重複せず、昼に星や月が残らないようにする。

## 4. 湘南海岸の太陽・順路・地形・景観

### 4.1 昼の太陽

- 湘南の昼の太陽を、滑らかな太陽円盤と自然な色・淡い光のにじみが感じられる見た目にする。粗い球体やベタ塗りの白丸にしない。
- 空の色、雲、海との調和を取る。海面への反射は、軽量に実現できる範囲で追加してよい。
- 道路や車が白飛びする強いブルーム、画面を覆うフレア、常時高負荷の反射処理は使わない。トンネルや建物越しに太陽が透けないこと。
- 太陽位置と主光源の向きを合わせる。日周運動や時刻のリアルタイム変化は今回追加しなくてよい。

### 4.2 スタート位置は島へ向かう橋に入る約600m前

ユーザーの追加指定により、基準点は**江の島へ向かう往路の橋の本土側入口**とする。「600m手前」は直線距離ではなく、正規進行方向に沿う道路中心線の距離。島側の橋の出口を基準にせず、600mに橋の区間は含めない。

- 新しいスタート／ゴールラインから往路の橋の本土側入口まで、中心線沿いに600mを目標としてスタート位置を移す。設計上の許容範囲は550～650mとし、実測距離を報告する。
- 基準は先頭車や最後尾車の位置ではなく、スタート／ゴールラインとする。8台のグリッドはその後方へ安全に収め、各車・CPUのランダム配置を維持する。
- 従来通り同じラインをスタートとゴールに用いる。ライン、ゴールバー、ミニマップ、グリッド、周回判定、チェックポイントをすべて新位置へ揃える。
- 初回のライン通過では周回加算せず、必要区間を順に走り2周した後の正規通過でゴールする。
- 改修8の順路を維持する。本土から橋の東側を通って島へ向かい、シーキャンドルを囲む島内のルートを一巡し、西側の橋で戻る。その後は海岸線を西へ走り、烏帽子岩を望み、市街地・江ノ電並走区間を経てスタート地点へ戻る。
- 設計上の南は「本土から島へ向かう方向」。方位の説明をゲームUIへ追加する必要はない。
- 全長は引き続き1周3～4kmを目標ではなく検収範囲とする。橋までの600m区間と島内の複雑化を両立するよう、本土側の線形・区間配分も調整する。

### 4.3 中央の高い丘と島全体の起伏

- 島のモチーフを江の島とし、中央が周囲より明確に高い丘となる地形へ作り直す。中央に置いた小さな山オブジェクトだけで代用せず、島の地面・道路・沿道を一体で起伏づける。
- シーキャンドルは丘の上に自然に接地させ、橋・海岸・島内から特徴的なシルエットが見える位置を保つ。
- 島の海岸縁から斜面、道路、中央丘陵まで自然につなぐ。道路には上り・下りと緩やかな頂上越えを組み合わせる。平面の周回道路の中心だけを盛り上げる変更にしない。
- 地形の高さや勾配はゲーム向けに調整してよい。実在の標高の完全再現を条件にせず、中央が高い島として認識できることと、全10車種の走行性を優先する。
- 急な段差、底打ち、タイヤ浮き、道路を覆う斜面、視界のない頂点直後の急カーブを避ける。路面・灰色路肩・芝生の高さを一致させる。
- 樹木・家・擁壁・灯台等を地形へ接地させる。高低差のある場所では擁壁や斜面を使い、宙に浮いた道路や不自然に薄い板状の地面にしない。
- 海上の橋は橋床・橋脚で支える既存構成を維持し、海を陸地で埋めて起伏を作らない。

### 4.4 レースとして変化のあるコース形状

- 単純な島の円周や大きな楕円をなぞるだけの線形を改める。
- 島内の上りS字、減速して旋回する中低速コーナー、緩やかな下りの連続カーブ、追い越しできる短い直線など、速度と操舵に変化が生まれる構成にする。
- 本土側にも海岸の高速区間と市街地の中低速区間の対比を作る。ただし西向きの海岸直線と江ノ電並走という既存の特徴は残す。
- 曲がり角を細かく増やすだけにせず、手前から先が読める線形、十分な道幅とランオフ、8台が競える追い越し区間を確保する。
- 最も大きい車種でも走れる旋回半径とする。全CPUレベル、とくにLv5の先読みとスペシャル使用を新線形で確認し、恒常的なコースアウトや詰まりがあれば道またはAIを調整する。
- スリップストリームとコーナーボーナスを維持する。区間数が増えてもボーナスは1周15％上限とし、周回／区間IDを新線形へ合わせる。
- 橋の往路・復路の判別、中央分離帯・欄干の衝突、正しい道路への復帰を再検証する。近接区間の誤選択で周回や距離が飛ばないようにする。

### 4.5 オブジェクトを軽量に増やす

- 海沿いの家屋・商店、低木・樹木、岩、石垣・擁壁、柵、街灯、沿道の小物などを追加し、海岸・島・市街地それぞれの場所の特徴を強める。
- 既存モデルの使い回しは許容する。回転・大きさ・色・配置を変え、同じ物が等間隔に並ぶだけの単調な景観を避ける。
- 共有メッシュ・材質、インスタンシングやバッチ化、距離での間引き・簡略化を活用する。装飾ごとのライト、不要なCollider、重い物理処理を増やさない。
- 重要なランドマークは走行中に見えるよう残し、小物で標識やコーナーの見通しを塞がない。走行路・路肩・コイン・復帰地点へ装飾を重ねない。
- コインは従来通り1周3地点、カーブ外側の走行可能な位置。新線形に合わせて再配置し、対向車線・分離帯・崖・海・線路に置かない。オンライン共有と2秒復活を維持する。

### 4.6 記録の互換性

- 今回は距離・勾配・線形・スタート位置が変わるため、湘南のレイアウトをv3として管理する。
- 改修8の `shonan-v2` と新しいv3のタイムを同じベスト／実測ランキングで比較しない。サーバー、ローカルベスト、履歴のレイアウト識別を揃える。
- 既存のv1・v2記録は旧レイアウトとして保管する。既存のv1保存領域へv2を上書きせず、複数世代を保持できる移行にする。
- 累計走行・勝利・ミッション・入手済みアイテム・装着位置・色・設定は保存する。過去の記録や報酬を勝手に消さない。
- 再読み込みや複数回の移行で重複付与しない。山岳・鈴鹿のコースと記録は変更しない。

## 5. アイテム獲得表示を2段に変更

- 新規アイテム獲得通知は、上段を大きめの「〇〇を達成！」、その直下を小さめの「〇〇をゲット」にする。
- 上段の〇〇は達成したミッション／条件、下段の〇〇は実際に獲得したアイテム名。上段にアイテム名を流用しない。
- 例:
  - 上段: 「初完走を達成！」
  - 下段: 「チェッカーピンをゲット」
- アイコンやアイテムのプレビューは残してよい。主情報は上記の2段とし、不要な説明文を増やさない。
- 既存条件の「最高速度100km/h達成」等へそのまま「を達成！」を足して「達成を達成！」としない。表示用の達成名を別に持つなど、30ミッションすべてで自然な日本語にする。
- メニューへ戻る際の既存報酬ダイアログをこの構成へ改修する。結果画面に獲得通知がある場合も、同じ条件名・アイテム名で統一する。既存の通知タイミングや閉じ方は不用意に変更しない。
- 同時に複数達成した場合はアイテムごとに条件と報酬を対にして表示する。長い条件名は改行し、スマホの画面内で読めるようにする。多い場合はスクロールできるようにする。
- 既存の `RacerItems` のID・条件・報酬名を対応付けに使い、表示中の言語に合わせて描画する。英語モードも自然な2段表示にする。
- 新規獲得だけ通知する。再接続、結果更新、再読み込みで二重付与しない。未確認の獲得通知の保存・復元と、ダイアログを閉じた後の入力復帰を維持する。
- ローカル記録と報酬は実測で完走した本人の結果を用いる従来仕様を維持し、CPU推計や他人の成績で報酬を得られる変更にしない。

## 6. 四輪車モデルのタイヤ位置・向き・接地の修正

ユーザーの追加指示: 四輪の位置ずれ、空中に浮いて見える状態、車体から外れて見える状態を修正する。四輪をそれぞれのホイールハウスに正しく収め、車体と路面に整合させる。修正した配置コードも提示する。

- 四輪車すべてを対象に、左前・右前・左後・右後のタイヤ、ホイール、ハブ、車軸の位置と向きを確認して修正する。車体中央だけを上下に動かして一部のずれを隠す対応にしない。
- 二輪車・三輪車など固有の構成は維持する。四輪配置を全車種へ一律に適用せず、それぞれの車種に合う接地と操舵を保つ。
- Blenderから出力した座標・スケール・回転と、Unity側のローカル座標・親Transform・ピボットを確認する。軸変換、二重のオフセット、意図しない非一様スケール、左右反転がずれの原因でないか調べる。
- 実際のモデル寸法に基づき、車種ごとの前後トレッド幅・ホイールベース・タイヤ半径・幅・取付高さを整理する。車体の左右中心線に対して適切に配置し、前後の車軸を対応するホイールハウスの中心へ合わせる。
- タイヤ上部はホイールハウス内に収め、下部は路面まで出す。タイヤ全体を車体内へ埋め込まない。車体から離れた隙間、シャーシのタイヤ貫通、車軸の外側への突き抜けを解消する。
- 水平路面で静止したとき、四輪の下端が路面に自然に接し、沈み込みや浮きがないこと。上り・下り・頂上・路肩でも、車体姿勢と接地表示を整合させる。路面判定は実際に走行している道路区間と高さを使い、立体交差の別の路面へ吸着しないようにする。
- 左右の車輪の車軸方向を車体の横方向に揃え、直進時のタイヤの転がる向きを進行方向に合わせる。ホイール表面の外向きと左右の回転方向も確認する。
- 前輪の操舵軸とタイヤの回転軸を分離し、正しい取付中心を支点に動かす。操舵時にタイヤが車体の周りを公転したり、回転のたびに位置がずれたりしないこと。最大操舵時にも車体へ不自然に食い込まず、後輪は不要に操舵しないこと。
- 既存の軽量なタイヤ回転表現を維持する。走行速度・重さ・グリップ等の能力値や当たり判定を、見た目の補正のために不用意に変更しない。新たな重い車両物理システムの導入を前提にしない。
- 主な確認先は `Art/Blender/build_assets.py` の車輪生成・ピボット設定・頂点出力と、`Assets/Scripts/RevisionSevenPresentation.cs` のモデル読込・操舵ピボット・回転処理。原因に応じて生成側と実行時側を修正し、編集用Blenderモデル・生成アセット・WebGL表示を一致させる。

### 配置コードの成果物

- 実装時は、修正した車輪配置コードをリポジトリへ保存し、`docs/REVISION_9_IMPLEMENTATION.md` にファイル名・関数名と該当コードを掲載する。説明だけ、実装と異なる疑似コード、未使用のサンプルで代用しない。
- 車種ごとの左前・右前・左後・右後の中心座標、基準回転、半径、使用座標系・単位・原点を表で示す。座標値はモデルを確認して決め、推測で共通値を固定しない。
- Blender側の生成コードとUnity側の位置・操舵・回転の設定のうち、実際に変更した部分を示し、どこでオフセットと軸変換が適用されるか説明する。
- 修正前後を同じカメラで比較する。四輪車ごとの正面・側面・斜め前、直進・左右最大操舵・走行中、水平路面と坂道で画像または動画を残す。図鑑・レース・ゴールカメラ・オンラインの他車表示でも配置が一致すること。
- 自動検証では車輪中心と取付位置、半径と路面高さ、回転後のピボット保持などを確認する。目視確認と組み合わせ、四輪が正しい場所に接続されていることを検証する。

## 7. 実装手順・検証・成果物

### 実装前

- 現行の関係箇所を読み、要件と変更対象の対応表を作る。主な確認先:
  - Web: `Assets/WebGLTemplates/CoastRacer/index.html`、`racer.js`、`club.js`、`club.css`、`items.js`。
  - 空と描画: `Assets/Scripts/MobilePresentation.cs`、`RevisionSevenPresentation.cs`、`RevisionEightPresentation.cs` と関連シェーダー。
  - コース・走行: `Assets/Scripts/Core/RaceCore.cs`、`RaceFeatures.cs`、`RacingExtras.cs`、オンラインサーバー。
  - Blender: `Art/Blender/build_assets.py`、`tracks.json`、編集用モデルと生成アセット。
- 湘南の新しい平面経路図と高低差の図を作る。スタート、往路の橋の本土側入口、島入口、東西の橋、丘・灯台、海岸西進、市街地・江ノ電、3コイン位置を示す。
- 全長3～4kmとスタートから往路の橋の本土側入口まで約600m（550～650m）を中心線から計測し、測定方法と値を記録する。

### 必須検証

- メニューの文字付き設定ボタンが消え、右上歯車から各設定を開閉・保存できる。削除後にJavaScriptエラーや空白がない。
- 全3コースの夜の星・月、湘南昼の太陽を、通常走行カメラ・ゴールカメラで確認する。昼夜切り替え、山や建物の背後、橋・トンネル、低画質でも不自然な透過がない。
- 湘南の昼夜・全10車種・CPUレベル1～5を含め、少なくとも10レースの自動走行を行う。全車2周完走、詰まり・復帰回数・異常速度を記録し、問題があれば調整して再試験する。
