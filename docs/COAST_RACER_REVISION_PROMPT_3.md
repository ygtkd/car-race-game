# COAST RACER 改修プロンプト3

## 目的・適用範囲
以下の実機報告に基づいて、COAST RACERを改修してください。原因は調査前に断定せず、実際の再現とコードの確認に基づいて修正してください。
本書は新規の追加改修指示です。既存プロンプトを上書きしないでください。優先順位は「最新のユーザー指示 ＞ 本書 ＞ COAST_RACER_REVISION_PROMPT_2.md ＞ それ以前の要望」です。本書で変更していない既存仕様を維持してください。
今回の依頼は本書の作成・保存までです。実装・push・Azure公開は、その後のユーザー指示に従ってください。

## R3-1. 道路周囲の灰色ゾーンの復活と減速（最優先）
ユーザーから、実機で道路周囲の灰色ゾーンがなくなっていたと報告されています。このゾーンの削除は指示されていません。過去の実装・Git履歴・描画を比較し、元の灰色ゾーンを復活させてください。単に道路を広げて代用しないでください。

| 路面 | 見た目・走行 | 復帰警告・強制復帰 |
| --- | --- | --- |
| 道路・縁石 | 既存の道路・縁石を維持 | 警告なし、復帰カウントなし |
| 灰色ゾーン | 道路周囲の元の領域を復活。進入すると通常の道路より減速し、アクセルを踏み続けても減速効果が分かる | 「コースに戻ってください」などの警告・秒数を表示しない。この領域にいることを理由に強制復帰させない |
| 緑の芝生 | 灰色ゾーンの外側にある芝生を維持 | 芝生上だけで5秒の復帰カウントを表示。時間切れで最後に走行していた道路区間の中心へ戻す |

- 灰色ゾーンの元の幅・配置・素材を履歴から確認し、山岳・鈴鹿の両コースに復元する。資料だけでは形状を判断できない場合に限り確認する。
- 道路／縁石／灰色／芝生を独立して判定する。「減速する場所＝復帰警告を出す場所」という共通条件にしない。
- 描画と路面判定の境界を一致させる。灰色ゾーンの表示だけを戻し、内部では芝生扱いにする修正は不可。
- 芝生から灰色ゾーンに戻った時点で復帰カウントと表示を解除する。再び芝生に入ると新しく5秒から開始する。
- 灰色ゾーン走行中に、復帰先を灰色ゾーンの中心へ更新しない。保存する復帰先は最後に走行した道路区間の中心・向きとする。
- 減速率は通常走行との差が明確で、道路へ戻れる操作性を保つ値に調整し、採用した値と確認結果を記録する。
- ソロ・オンライン・CPUで路面判定を統一し、高低差や立体交差で別の道路区間に誤判定しない。

## R3-2. 一時停止後の操舵・スペシャルゲージの不具合
一時停止後にハンドルが曲がらない、スペシャルゲージがたまらない現象が報告されています。一時停止が原因と断定せず、設定画面・フォーカス・入力・時間・通信状態も含めて調べてください。

- 操舵、アクセル、ブレーキを押している最中に一時停止しても、入力が押しっぱなしになったり、復帰後の新しい入力が無視されたりしないようにする。
- 一時停止・設定画面・確認ダイアログを開く際には、保持中の入力とポインター状態を解放する。復帰後は新しいタッチで即座に操作できること。
- ソロは一時停止中に走行距離やゲージが増えず、復帰後は実際の走行距離・コインによって正常に増えること。
- オンラインはローカルの一時停止／設定表示で他の参加者のレースを止めない。入力解除と復帰、サーバー状態との同期を確認する。
- ゲージの既存仕様（おおむね1.2周の距離で満タン、コイン1枚で0.5周相当）は維持する。復帰時に不当にリセット・満タン・二重加算しない。
- 特殊技の使用前・発動中・終了後それぞれで停止／復帰し、ゲージ蓄積と再使用が正常であることを確認する。

## R3-3. 操舵の細かい連打で曲がりっぱなしになる問題（最優先）
カーブでハンドルを細かく連打すると、指を離しても曲がりっぱなしになる問題を修正してください。

- pointerdown/up/cancel、ポインターキャプチャの解除、指が判定外へ移動した場合、フォーカス喪失、画面の非表示・復帰を確認する。
- 操舵中のポインターIDを正しく管理し、ペダルとの同時操作や別の指の離脱が操舵の解除・継続を誤らせないようにする。
- 左の連打、右の連打、左右交互の連打、長押しから連打への切替、判定外で指を離す操作を確認する。
- 指が離れた時点で操舵入力を中立に戻し、既存の自然なハンドル復帰を行う。旋回の慣性と、入力が残っている不具合を区別して検証する。
- イベントリスナーや入力ループが画面遷移・再戦・再接続で重複しないこと。連打を無効化するだけの対処や、通常操作を鈍くする大きな待ち時間は導入しない。
- R3-2と共通する原因はまとめて修正するが、各報告の再現ケースは個別に検証する。

## R3-4. 各車のスペシャルを派手で分かりやすくする
全8車種の既存のスペシャルについて、発動したことと効果が直感的に分かる演出へ改善してください。

- まず車種名・既存効果・発動条件・持続時間を一覧化する。今回の目的は演出改善であり、技を一律に加速へ置き換えたり、理由なく性能を変更したりしない。
- 車種・効果に応じた色、発光、軌跡、衝撃波、粒子などを組み合わせ、技ごとに見分けられる演出を設計する。
- ゲージ満タン、発動、効果継続、終了が分かるようにする。必要な短い技名・アイコンは使用してよいが、長い説明文で画面を覆わない。
- 加速なら速度感、妨害なら範囲・対象・被影響状態など、実際の効果に沿った表示にする。見た目だけ広くして効果範囲を誤認させない。
- 自分・他プレイヤー・CPUの発動が見え、オンラインで同じ発動を重複再生しない。終了・切断・レース終了後にエフェクトを残さない。
- 道路・信号・操作ボタンを覆わず、激しい点滅や過度な画面揺れを避ける。効果音は既存のSE音量とミュート設定に従う。
- スマホWebGLの負荷を測定し、既存の描画品質設定に応じた軽量化を行う。車種ごとの変更前後の画像または動画を残す。

## R3-5. 木の形を現実に近づける
現在の木を、単純な柱や一体の丸い塊に見える形から改善してください。

- 幹・枝・葉のまとまりを分け、樹冠の不規則さ、幹の太さ、自然な枝分かれが分かる形にする。
- 山岳・サーキット周辺に合う木を用い、高さ・幅・向き・葉色に自然な変化を付ける。同じ形を等間隔に並べただけの景観を避ける。
- 道路、灰色ゾーン、走行可能範囲を木で塞がない。既存のコース形状や道路周囲の領域を変更して対応しない。
- 近景の輪郭を改善し、遠景は軽量な表示にする。描画負荷・メモリー・読み込み容量を確認し、スマホで多数の木が映る場面を検証する。
- 外部素材を使用する場合は入手元と利用条件を記録する。生成・自作の場合も作成方法を記録する。

## 検証・報告
- 作業開始時に公開版・ローカル版・実機のBuildを照合する。実機の版が不明なら未確定と記録し、キャッシュが原因と決めつけない。
- 各R3要件について、再現手順、期待動作、修正箇所、実際の結果、証拠、未確認事項を対応表にする。
- 路面テスト: 両コースで道路→灰色→芝生→灰色→道路を走行し、速度・警告・残り時間・復帰先を確認する。灰色で5秒以上走行しても強制復帰しないこと。
- 操作テスト: ソロとオンラインで、操舵＋アクセル同時押し、一時停止10回以上、左右の連打30回以上、設定開閉、再戦、画面外での指離し、バックグラウンド復帰を確認する。復帰後の走行距離・コインによるゲージ蓄積も確認する。
- 特殊技テスト: 全8車種の発動・継続・終了と複数台同時発動、オンライン表示、ミュート、停止・復帰を確認する。
- iPhone・Galaxy・Google Pixelのブラウザー起動とホーム画面起動を対象とする。実機がなければ未検証と明記し、エミュレーション結果を実機合格と呼ばない。機種・OS・ブラウザー・Buildを記録する。
- 既存の開始文字非表示、右上設定ボタン、2周、ゴール判定、CPUのみのタイム推定、オンライン最大8台、バッジ・プロフィール・音量設定に回帰がないことを確認する。
- 実装、ローカル検証、push、Azure公開、実機検証を別々の状態で報告する。実機不具合が解消したと確認できていない場合は、その限界を明記する。
