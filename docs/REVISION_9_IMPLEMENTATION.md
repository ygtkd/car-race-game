## 描画負荷と制約

湘南の追加樹木を簡略化し、三角形を104,818から79,426へ約24％削減。改修8は67,432。材質とメッシュを共有し、星ごとのオブジェクトやライトは追加していない。月の細部は月が見える画素だけ計算し、昼の星空処理を省略した。

以下はHeadless Edge／SwiftShader、1100×650、各地点120フレームの静止場面をrequestAnimationFrameで測った値。実機のGPU計測ではない。新旧で道路位置・標高・構図が変わるため、純粋な同一景観比較ではない。中央値にばらつきがあるため、95パーセンタイルも併記する。

| Scene | Before median / p95 (ms) | After median / p95 (ms) |
|---|---|---|
| start day | 49.8 / 66.7 | 16.8 / 66.7 |
| start night | 66.6 / 83.3 | 66.6 / 83.3 |
| hill day | 33.3 / 50.1 | 49.8 / 66.7 |
| hill night | 49.9 / 66.7 | 49.9 / 83.3 |
| town day | 16.8 / 50.1 | 49.9 / 66.7 |
| town night | 16.7 / 83.2 | 66.5 / 83.3 |

昼の丘陵・市街地区間は初期目標の「悪化10％以内」を満たしていない。モデル簡略化とシェーダーの条件分岐を行ったが、追加景観・地形と構図の変化を含む負荷増が残る。実機での性能確認は必要。これを性能面の未確認事項として残し、「負荷が増えていない」とは扱わない。

- iPhone／Galaxy／Pixel相当の画面サイズ・タッチはデスクトップで模擬。実機・発熱・連続走行性能・人間による試走は未確認。
- 昼夜の描画と自動入力によるオンラインを確認したが、Azure Free上の8人継続負荷は未確認。
- 新規インストールなし。既存Blender 5.2.2 LTS／Unity 6000.6.2f1／.NET／Python／Node.jsを使用。
- CarController.csの既存ユーザー変更は未編集・今回のビルドへ未取り込み。空き容量1GiB停止ガードを維持。
