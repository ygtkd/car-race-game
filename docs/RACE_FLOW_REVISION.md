# レース進行・オンライン改修

## 実装
- 歯車は右上。一時停止はHUDヘッダー右端。スタート文字と通常のコース外警告を削除。
- 表示ゴールラインの中心面を車体前端が正方向に横切ることで2周を確定。前後位置の掃引判定とチェックポイント順序を併用。接触による移動も次の更新で判定する。
- 芝生（縁石外側8.1m以遠）の逸脱を5秒カウントし、逸脱直前の道路上の位置に対応する中心線へ復帰。高さと道路区間を維持。復帰の3秒加算・2秒接触保護は継続。
- ソロは人間の完走時に未完走CPUの残距離・車種最高速・コース曲率からタイムを推定。推定は≈で区別。
- オンラインは自分の完走直後から結果表示を更新。残り1台は記録なし、未完走がCPUだけなら推定で終了。同じ更新内の同時ゴールは実測を優先。
- 人間の実測完走だけを端末記録・SQLランキングに保存。CPU実測・CPU推定・人間の記録なしはランキング対象外。SQLスキーマ変更なし。
- マルチ選択直後に部屋作成・参加と参加可能ルーム一覧。ホストだけがコースとCPU数を選択。人間＋CPUは最大8台。全員決定・ロード完了後に開始。
- CPU枠を含め満員なら参加不可。ゲストは自分の車体だけを変更可能。ホスト退出時は残る人間へ移譲。
- バナナボートは船体1本。衝突幅も縮小。新規獲得バッジをメニューへ戻る前に表示。
- 山並み・遠景と雲をオリジナルの軽量シェーダーで描画。外部素材・追加インストールなし。

## 通信の終了
- 明示退室は通常クローズ（1000）で即時離脱。ソケットのハンドラー・タイマー・入力・参加情報を解除。
- 一時的な通信断は20秒の再接続猶予。期限後は離脱扱い。人間のタイムを推定することはない。
- クライアントの無応答監視は15秒。不正JSON・不正通知・送信例外は接続終了。古いソケットの通知は無視。
- サーバーは未参加で15秒、参加後に受信が30秒途絶えた接続を解放。送信が3秒以内に完了しない場合も中断し、受信待ちを解除。
- 不正JSON・不正形式の接続は切断。接続枠はfinallyで解放する。

## 検証と制約
- Unity 6000.6.2f1 WebGLビルド成功。共通走行テストではゴール境界、逆走、高さ違い、復帰、CPU推定、人間推定禁止、8車種完走を検証。
- 32レース128台分の既存バランステストに加え、両コース8台同時完走を検証。
- 実WebSocketの2人レースで両コース2周、最下位の記録なし、結果一致、再戦を確認。
- 人間2人＋CPU6台、および人間8人の実通信でルーム権限・満員・ロード待ち・開始同期を検証。8台の状態通知は約6.3KB（20Hz、接続人数に応じて送信量増加）。
- 無料F1での継続的な8人負荷、実機iPhone・Galaxy・Pixelの性能は未検証。ローカルの機能検証をAzureの性能保証として扱わない。
- ブラウザー検証はデスクトップEdgeのタッチエミュレーション。検証結果はLogs/flow-*.logとLogs/club-browser-checks.jsonに記録する。
